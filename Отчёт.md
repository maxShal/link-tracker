# Отчёт: клиент-серверное приложение LinkTracke

## 1. Доменная область

LinkTracker предназначен для отслеживания ссылок на репозитории GitHub и вопросы Stack Overflow. Пользователь сохраняет интересующие его ссылки, организует их с помощью тегов и получает уведомления об изменениях через Telegram.

У приложения два пользовательских интерфейса: Telegram-бот и веб-страница. Страница позволяет просматривать подписки выбранного чата, добавлять и удалять ссылки, добавлять и удалять теги. Сервер периодически опрашивает внешние API и передаёт обнаруженные обновления боту. Для GitHub отслеживаются события issues и pull requests; произвольный новый коммит не является самостоятельным поддерживаемым сценарием уведомления.

История уведомлений на веб-странице пока не реализована. Данные о подписках общие для сайта и Telegram, но доставка уведомлений выполняется только в Telegram.

## 2. Стек реализации и архитектура

| Компонент | Технологии и назначение |
| --- | --- |
| Backend | Java 25, Spring Boot, Spring MVC, HTTP API|
| Frontend | HTML, CSS, JavaScript|
| Хранение данных | PostgreSQL; в основном Compose указан образ `postgres:18.6` |
| Доступ к данным | В активной конфигурации JDBC; в исходниках также есть реализация на JPA |
| Миграции | Liquibase, SQL-файлы в ресурсах scrapper |
| Сборка | Maven |
| Упаковка|Docker, Docker Compose|
| Проверки | JUnit, Mockito, Spring Boot Test, Testcontainers; интеграционные проверки с PostgreSQL |
| Внешние системы | GitHub API, Stack Exchange API, Telegram Bot API |

Основной вариант развёртывания состоит из трёх сервисов:

1. **scrapper** хранит и обрабатывает подписки, предоставляет HTTP API, отдаёт статические файлы сайта и выполняет периодические проверки ссылок. Доступен с хоста на порту `8081`.
2. **bot** принимает команды Telegram, обращается к API scrapper и принимает обновления на своём HTTP-порту `8080`. Этот порт доступен между контейнерами; в основном Compose он не опубликован на хосте.
3. **postgres** хранит чаты, ссылки, теги и связи между ними. Данные сохраняются в каталоге `./pgdata`, подключённом к контейнеру.

Kafka, Valkey и ai-agent не запускаются в основном варианте Compose. Связь scrapper с bot настроена через HTTP.

## 3. Основные сущности

| Сущность | Представление и назначение |
| --- | --- |
| Чат | Таблица `chats`: идентификатор Telegram-чата, для которого зарегистрированы подписки |
| Ссылка | Таблица `links`: идентификатор, уникальный URL и временная отметка `last_updated_at`, используемая при обработке обновлений |
| Подписка | Таблица `link_chat`: связь чата и ссылки; несколько чатов могут отслеживать одну ссылку |
| Тег | Таблица `tags`: уникальное текстовое имя тега |
| Связь ссылки с тегом | Таблица `link_tag`: связь между ссылкой и тегом |

## 4. Пользовательские операции и CRUD

Для запросов к ссылкам и тегам клиент передаёт заголовок `Tg-Chat-Id`. На странице пользователь вводит ID зарегистрированного чата.

| Операция | HTTP API | Доступность |
| --- | --- | --- |
| Create: добавить подписку | `POST /links` | Веб-страница и бот |
| Read: получить подписки | `GET /links` | Веб-страница и бот; список поддерживает страницы |
| Delete: удалить подписку | `DELETE /links` | Веб-страница и бот |
| Create: добавить теги | `POST /tags` | Веб-страница |
| Read: получить теги ссылки | `GET /tags?url=...` | HTTP API, используется страницей при обновлении тегов |
| Update: переименовать тег | `PUT /tags` | Метод API существует, но содержит ошибку, описанную ниже |
| Delete: удалить тег | `DELETE /tags` | Веб-страница |

## 5. Соответствие методологии 12 факторов

### I. Кодовая база


Код хранится в Git. Модули bot, scrapper и фронтенд входят в один многомодульный проект; варианты окружения не требуют копирования исходников в отдельные проекты. Dockerfile, миграции и Maven-конфигурация версионируются вместе с кодом.


### II. Зависимости

Явно объявлены и изолированы.
### III. Конфигурация

Токены, параметры БД и адреса внешних сервисов передаются через переменные окружения. Compose получает значения из локального `.env` и передаёт их контейнерам. `.env` исключён из Git.

### IV. Сторонние службы

PostgreSQL и внешние API доступны через настраиваемые адреса и учётные данные. 

### V. Сборка, релиз и выполнение

Сборка Maven создаёт JAR. Dockerfile упаковывает уже собранный JAR в образ. При выполнении контейнер запускает `java -jar`, а конфигурация поступает из окружения. Исходники внутри работающего контейнера не компилируются.

Однако процесс релиза пока не оформлен как неизменяемый набор «конкретный образ + конфигурация». В основном Compose нет явных уникальных версий образов bot и scrapper. Для надёжного отката нужно публиковать образы с уникальными тегами, например Git commit SHA, и фиксировать состав каждого развёртывания.

### VI. Процессы

Основные данные находятся в PostgreSQL. HTTP-запросы сайта не зависят от серверной HTTP-сессии.

### VII. Привязка портов

Сервисы запускаются как самостоятельные Java-приложения со встроенным HTTP-сервером. Scrapper предоставляет сайт и API на `8081`; bot принимает HTTP-обновления на `8080`. Отдельная установка сервера приложений не нужна.

### VIII. Параллелизм

Bot и scrapper уже являются отдельными процессами.

### IX. Быстрый запуск и корректное завершение

JSON-форма `ENTRYPOINT` запускает Java непосредственно, что позволяет процессу получать сигнал остановки контейнера. Для пула проверки ссылок указан `destroyMethod = "shutdown"`. Основные данные сохраняются в PostgreSQL.

Вместе с тем одного вызова `shutdown` недостаточно, чтобы гарантировать завершение всех внешних запросов и доставку уведомлений до остановки контейнера. Незавершённый диалог бота теряется. Нет подтверждённого испытания остановки под нагрузкой с проверкой отсутствия потерь и повторов.

Для полного подтверждения нужно согласовать время завершения приложения и контейнера, проверить остановку во время отправки уведомления и определить восстановление незавершённой обработки. Скорость старта в этом отчёте не измерялась.

### X. Сходство окружений


Docker Compose описывает воспроизводимое окружение, а основные интеграционные тесты scrapper используют настоящий PostgreSQL через Testcontainers. В базовом классе этих тестов указан тот же `postgres:18.6`, что и в основном Compose. Схема создаётся миграциями из репозитория.

### XI. Журналирование

Сервисы выводят сообщения через используемый механизм логирования в консоль.
### XII. Административные задачи

Миграции Liquibase хранятся рядом с исходниками и используют конфигурацию БД приложения. Это обеспечивает связь схемы с версией кода.
