# Развёртывание LinkTracker в Kubernetes

## Использованные абстракции

- Namespace linktracker объединяет объекты приложения.
- Deployment scrapper и bot управляют ReplicaSet и подами Java-приложений.
- Service scrapper и bot дают постоянные внутренние DNS-имена и направляют
  запросы к готовым подам по меткам app.
- StatefulSet postgres запускает одну реплику БД со стабильным именем postgres-0.
- Headless Service postgres обеспечивает сетевое имя PostgreSQL.
- volumeClaimTemplates создаёт PVC data-postgres-0 на 1 GiB.
  StorageClass standard в minikube выделяет PersistentVolume.
  Данные переживают пересоздание пода; удаление кластера не является способом
  сохранения данных или резервного копирования.
- ConfigMap хранит адреса и несекретные параметры.
- Secret передаёт пароль БД и внешние токены как переменные окружения.
- initContainers ожидают доступности PostgreSQL перед запуском приложений.
- startupProbe, readinessProbe и livenessProbe проверяют запуск и доступность
  контейнеров. Для Java используется проверка TCP-порта.

## Взаимодействие

Браузер через kubectl port-forward обращается к scrapper:8081.
Scrapper отдаёт HTML/CSS/JavaScript и HTTP API, хранит чаты, ссылки и теги
в PostgreSQL по адресу postgres:5432. Liquibase создаёт схему.
Bot получает команды через Telegram API и вызывает scrapper:8081.
Scrapper опрашивает GitHub и Stack Exchange API и отправляет обновления
по HTTP на bot:8080/updates; bot доставляет их в Telegram.
Kafka, Valkey и ai-agent в данном варианте не используются.

## Сборка и масштабирование

Dockerfile упаковывают предварительно собранные Maven JAR.
Используются локальные образы linktracker-bot:hw2 и linktracker-scrapper:hw2
с imagePullPolicy IfNotPresent. PostgreSQL использует postgres:18.6,
как основной Docker Compose проекта.
Демонстрация предусматривает масштабирование Deployment scrapper с одной
до трёх реплик и возврат к одной.
Планировщик scrapper выполняется в каждой реплике: возможны повторные
проверки и уведомления. Координация фоновых задач пока не реализована.
Bot работает в одной реплике из-за polling и состояния диалогов в памяти.
База работает в одной реплике без автоматической репликации.
