# Развёртывание LinkTracker в Kubernetes

Для запуска приложения использован одноузловой кластер minikube. В нём работают три компонента: bot, scrapper и PostgreSQL.

## Файлы

- `bot/Dockerfile` и `scrapper/Dockerfile` - упаковывают собранные JAR в Docker-образы для запуска сервисов.
- `k8s/00-namespace.yaml` - создаёт пространство имён `linktracker`, в котором размещены все компоненты приложения.
- `k8s/01-config.yaml` - создаёт ConfigMap с именем БД, адресами сервисов и настройками приложения.
- `k8s/02-postgres.yaml` - запускает PostgreSQL через StatefulSet. Service даёт базе адрес `postgres:5432`, а PVC сохраняет данные при пересоздании пода.
- `k8s/03-bot.yaml` - создаёт Deployment для бота и Service на порту 8080. Бот получает команды из Telegram и обращается к scrapper.
- `k8s/03-scrapper.yaml` - создаёт Deployment для scrapper и Service на порту 8081. Scrapper предоставляет веб-интерфейс и API, работает с БД и проверяет обновления ссылок.
- `k8s/secrets.local.yaml` - создаёт Secret с учётными данными PostgreSQL и токенами внешних API.

## Команды

Запуск кластера:

```powershell
minikube start
```

Сборка образов и проверка их наличия в minikube. Dockerfile используют предварительно собранные JAR из каталогов target:

```powershell
docker build -t linktracker-bot:hw2 ./bot
docker build -t linktracker-scrapper:hw2 ./scrapper
minikube image ls
```

Развёртывание приложения и просмотр ресурсов:

```powershell
kubectl apply -f k8s/00-namespace.yaml
kubectl apply -f k8s/
kubectl get namespace
kubectl get pods -n linktracker
kubectl get pods -n linktracker
```

Доступ к веб-интерфейсу:

```powershell
kubectl port-forward service/scrapper 8081:8081 -n linktracker
```

Страница доступна по адресу http://localhost:8081.

Для демонстрации масштабирования нужно выполнить:

```powershell
kubectl scale deployment scrapper --replicas=3 -n linktracker
kubectl rollout status deployment/scrapper -n linktracker
kubectl get pods -n linktracker
kubectl scale deployment scrapper --replicas=1 -n linktracker
```
Bot и PostgreSQL остаются в одной реплике. При увеличении числа реплик scrapper фоновые проверки выполняются в каждой из них, поэтому будут повторные уведомления.
